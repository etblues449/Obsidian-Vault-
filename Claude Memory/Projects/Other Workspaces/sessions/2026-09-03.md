# 2026-09-03 — Obsidian CLI setup (`obsidian:obsidian-cli` skill)

Request: complete the setup for the `obsidian:obsidian-cli` skill.

## The constraint that shapes everything

The Obsidian CLI is a **client**, not a vault reader. It opens a socket to a
running Obsidian desktop app and asks it to act. No app running, no CLI. So
"setting up the skill" means installing and running the desktop app wherever the
CLI is meant to work, not installing a CLI package.

No device bridge in this session — the cloud container cannot reach the PC or the
Fold. So the work split in two: make it genuinely work here, and ship a tested
setup path for the PC.

## Three findings worth keeping

1. **The "Command line interface" toggle is just `"cli": true`** at the top level
   of `obsidian.json` (`~/.config/obsidian/` on Linux, `%APPDATA%\obsidian\` on
   Windows). Found by reading the ipc handler in `obsidian.asar`. That is what
   lets both setup scripts here enable it without touching the GUI.
2. **`XDG_RUNTIME_DIR` is the trap.** The socket is
   `$XDG_RUNTIME_DIR/.obsidian-cli.sock`, falling back to `$HOME`. Containers
   hand out an inconsistent value between shells, so the app creates the socket
   in one place and the CLI looks in another — presenting as "unable to find
   Obsidian" while the app is plainly running. Both wrappers unset it.
3. **Electron segfaults if it beats the X server up.** A fixed `sleep 2` after
   starting Xvfb worked once and then segfaulted on a cold run. The launcher now
   waits for `/tmp/.X11-unix/X99` and retries the app up to three times. Caught
   by deliberately tearing the environment down and re-running, not by guessing.

## Safety check — auto-writer plugins

`obsidian-git` is enabled in this vault with `autoSaveInterval: 10`,
`autoPushInterval: 10`, `autoPullOnBoot: true`, `disablePush: false`. A headless
instance loading it would be an unattended client pushing to `master` every ten
minutes — the same shape as the still-open *"identify the client that deleted 8
files from master"* item.

Checked, not assumed: `app.plugins.plugins` is **empty** (Obsidian opens an
untrusted vault in Restricted Mode) and the clone stayed **0 commits ahead of
origin**. The bootstrap now asserts this every run and calls
`app.plugins.disablePlugin()` — the runtime-only call — on anything risky that
did load.

## Not done, and why

- **Windows setup was not executed.** No bridge to the PC from this session. The
  PowerShell is parse-checked and its logic unit-tested under PowerShell 7.5.3,
  but it has not run against a real Obsidian install. Run
  `Setup-ObsidianCli.ps1` (no `-Fix`) first — it changes nothing and reports.
- **Android/Termux is not possible.** The CLI ships inside the desktop Electron
  app; the Android build has no CLI and Termux cannot run the desktop app. The
  existing Advanced URI plugin, claude-code-bridge and plain `git` remain the
  route on the Fold. Recorded so it is not re-investigated.
