# Session 2026-08-03 — ai_cam into Frigate via go2rtc (LIVE)

Continuation of [[2026-08-02]] (PR #73). Ends with **Frigate detecting and recording
off the living-room AI Cam** — verified by screenshot, not inferred.

Full recipe: [[../hardware/ai_cam-go2rtc-frigate]].

## Delivered

- **ai_cam is now a Frigate camera.** ESPHome MJPEG `:8080` → go2rtc (single client
  slot, libx264 transcode, 1 keyframe/sec) → RTSP `:8654` → Frigate detect + record.
  WebRTC fans out to browser and Fold 7 off the same producer.
- go2rtc config, Frigate config and the diagnostic method written up in the hardware note.

## Two things I got wrong, corrected in-session

1. **Invented an ESPHome `rtmp_server` component.** Added to [[../hardware/ai_cam]] in
   `295d0f4`, reverted in `787a2d6` after checking esphome.io's component index —
   no such component exists. Would have failed Device Builder validation and blocked
   the next flash. ESPHome offers MJPEG-over-HTTP and snapshot, nothing else.
2. **Said "yes" to people being able to talk through the camera speaker via go2rtc.**
   Wrong. WebRTC 2-way audio needs a camera-side backchannel (ONVIF / RTSP ANNOUNCE);
   the board's MJPEG has no audio track either direction and the producer strips it
   with `-an`. The reachable path is the media_player entity
   (`media_player.living_room_ai_cam_ai_cam_speaker`) via `tts.speak` — works today,
   no reflash, but no live push-to-talk.

## Debug trail worth keeping

- Frigate crash-looped on `rtsp://127.0.0.1:8554/ai_cam: 404 Not Found`. The 404 means
  go2rtc has the stream **named** but its producer yielded no tracks — the Frigate log
  can only ever show that symptom. **The go2rtc log is the one that names the cause.**
- Root cause was a **trailing slash**: `:8080/#video=h264` vs the working
  `:8080#video=h264`.
- Two YAML errors on the way in: `port :` with a space before the colon, and `streams:`
  / `webrtc:` indented under `api:` instead of as siblings.
- Corrected two names I would otherwise have guessed: Frigate's MJPEG preset is
  `preset-http-jpeg-generic` (not `-mjpeg-`), and go2rtc's encoder args are overridden
  via the `ffmpeg:` config section, with `#raw=` for one-offs.

## Decisions

- **Standalone go2rtc on RTSP `:8654`, not 8554.** Frigate ships its own embedded
  go2rtc that binds 8554; an explicit distinct port means `rtsp://…/ai_cam` can never
  silently resolve against the wrong instance. Frigate's `go2rtc:` block removed.
- **`-g:v 5` overriding go2rtc's default `-g 50`.** Default was a keyframe every 10s
  at 5fps, which makes Frigate clips start late and seek badly.
