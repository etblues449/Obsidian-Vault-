## Decisions made

- **Package, not `automations.yaml`.** The Frigate HA integration is not installed, so
  Frigate's detections exist only as MQTT topics, and MQTT entities cannot be created from
  the automation UI. A package keeps entities, helpers, script and automations installable
  and removable as one unit.
- **Frigate's person count is converted to a `binary_sensor` once**, and every automation
  triggers on the `off`→`on` edge. This fixes "every MQTT count update re-triggers it" at
  the source instead of guarding against it in five places, and unlocks `for:` durations.
- **Cooldown = `mode: single` + a trailing `delay`.** No helper, and specifically no
  self-referencing `last_triggered` template, which breaks silently when an alias is renamed.
- **Automations 2 and 4 made mutually exclusive** via `input_boolean.ai_cam_simple_alert_only`
  — a deviation from the handoff's flat list. Built literally they would fire together on one
  satellite with one speaker, and the challenge would lose its answer to the announce talking
  over it. The validator asserts the guards stay opposites.
- **Privacy-follows-presence ships inert.** Enabling it stops detection while home, which
  also silences the person→light automation while home. Real trade-off, Elliot's call.
- **`start_conversation` still not used.** Unblocking it means pointing the pipeline at the
  "Claude" conversation agent, which routes all voice commands through the LLM. That is a
  standing decision, not something an automation file should change silently. `ask_question`
  bypasses the conversation engine entirely and needs none of it.
- **The unresolved legacy notify service name is resolved by tooling, not guessed at.**
  The text alert always goes out over the verified `notify.send_message` entity path first;
  the image attachment is a best-effort second call, so a wrong guess costs the picture, not
  the alert. Preflight enumerates the hub's real `notify.mobile_app_*` services and names the
  correct one.
